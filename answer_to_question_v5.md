ВОПРОС: Какие уровни изоляции транзакций в MySQL вы использовали для защиты от фантомных чтений?
ОТВЕТ:
В проекте используется уровень изоляции транзакций по умолчанию для движка InnoDB — REPEATABLE READ.
В MySQL/InnoDB этот уровень уже защищает от фантомных чтений благодаря комбинации двух механизмов:
MVCC (многоверсионное управление параллельным доступом) — позволяет транзакции видеть согласованный снимок данных на момент начала запроса.
Next-Key Locking — блокирует не только найденные строки, но и промежутки между ними, что предотвращает вставку новых строк ("фантомов") другими транзакциями в проверяемый диапазон.
Явно переключаться на уровень SERIALIZABLE не потребовалось, так как для сценария бронирования применена комбинированная защита:
Критическая часть кода (проверка свободного слота + вставка записи) обёрнута в транзакцию (BEGIN ... COMMIT/ROLLBACK).
Перед INSERT выполняется повторный SELECT COUNT(*) с теми же условиями (оптимистическая блокировка).
При работе с расписанием используется SELECT ... FOR UPDATE, который ставит эксклюзивные gap-locks на диапазон времени конкретного специалиста, полностью исключая возможность фантомных вставок конкурентными запросами.
Таким образом, стандартный REPEATABLE READ вместе с транзакционной логикой и явными блокировками FOR UPDATE обеспечивает надёжную защиту от фантомных чтений без потери производительности, характерной для SERIALIZABLE.
